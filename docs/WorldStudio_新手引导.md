# World Studio 新手引导

> 世界观工坊 · 从只言片语到一份世界观文档
> 适用版本 **v2.27** · Novel Jazz Engine
>
> 另见 Word 版：`docs/WorldStudio_新手引导.docx`（由 `python tools/make_manual_world.py` 生成）

---

## 一、这是什么（60 秒了解）

World Studio（世界观工坊）是 JazzWriter 里与「小说编排」并列的**独立模块**：有自己的启动入口、自己的窗口、
自己的数据目录（`worlds/`）。它帮你从一小段灵感长出一个世界，也能导入已有设定进行改造。

**最终产物是一份 Markdown 文档 `world.md`** —— 结构化、带来源、带状态、可继续打磨。

两件刻意的设计：

- **先发散、再收敛**：同一个灵感被解释成多个**底层逻辑不同**的世界原型，由你来选。
- **把世界当假设**：每条设定都有**状态**（已确认 / 候选 / 未决 / 有意保留的矛盾）、**依据**与**来源**；
  系统只提示冲突、不擅自修改，裁决权始终在作者。

## 二、安装与启动

前提：已安装 Python（3.9+）。图形界面只用标准库 Tkinter，无需额外安装。

- **双击启动**：双击项目根目录的 `WorldStudio.bat`。
- **命令行**：`python world_studio_gui.py`（界面） / `python world_studio.py --help`（命令行）。

默认使用真实模型 **opencode**（复用你已登录的模型，含 OpenCode Go 订阅）；离线时把「模型」切到备选 **mock**，
无需任何 API Key 即可跑通（内容偏骨架化，但结构、依据、状态、导出齐全）。接入真实模型见第八章。

## 三、5 分钟快速上手

1. **写下一句灵感**（一句话即可）：`每个人死后都会留下一段从未说出口的记忆，但只有建筑能听见。`
2. **发散**：点「发散」。左侧出现世界原型（**默认 4 个**，可用 `--count 3–6` 调整）。选中任意一个，
   右侧会列出它在**五个维度**上的不同：**规则机制 / 权力结构 / 知识分配 / 人物困境 / 时间动力**，
   并显示差异度；"标签不同但机制重复"的会标 ⚠。发散后自动保存到 `worlds/<名称>/`。
3. **选择并生长**：选中一个原型 →「选择并生长」。系统先由核心规则推出**结构属性**
   （可观测性 / 稀缺性 / 执行方式 / 代价 / 可变性，带证据与把握度；无法判断标"未知"并给出待确认问题），
   再推导出 社会后果 / 知识与认知 / 制度与权力 / 历史动力 / 地理与空间 / 冲突与人物 / 意象与母题。
4. **查看与编辑**：右侧实时显示 `world.md`；在「设定条目」里可把任意条目标为
   已确认 / 候选 / 未决 / 矛盾，或**锁定**（再次生长不会覆盖）。
5. **一致性检查**：查看疑似冲突（含依据与把握度）。离线模式会声明"不做语义判断"，
   因此"未发现冲突"不等于"与核心规则一致"。
6. **继续 / 导出**：`worlds/<名称>/world.md` 已生成，也可「另存副本」。
   下次在上方「已有世界观」下拉选择并「打开」，**种子与原型列表会一并恢复**。

## 四、设定嫁接：改造已有世界观

在左侧「设定嫁接」选一种操作 →「导入设定文件并变形」选择 `.txt / .md`。系统先抽取
**抽象骨架**（规则 / 主题 / 权力 / 历史 / 美学），再生成**结构化变形计划**，据此产出新的核心规则与后果链。

| 操作 | 目标 |
| --- | --- |
| 深度变形 | 保留少量核心规则，重新推导社会、历史与生活方式 |
| 主题移植 | 保留主题矛盾，改换时代、制度与技术条件 |
| 世界交叉 | 从两个设定中选择可兼容的规则，再处理冲突（**需第二份材料**） |
| 边缘扩展 | 保留原世界底层逻辑，创造此前未重点描写的区域或时代 |
| 反转前提 | 改变一条关键假设，观察整个世界的连锁变化 |

- **默认派生新世界**：源世界文件不被改动，结果保存到新的目录名下。
- **世界交叉必须有第二份材料**：GUI 会再让你选一个文件；命令行需 `--second <文件>`，否则报错。
- 文档会写清 继承 / 删除 / 修改 / 新增 / 下游影响 与来源；新增规则标为"候选"。

### 典型用法：导入**另一个项目**的 `world.md`

这是嫁接最主要的用法。系统读的是那份设定的**抽象骨架**（规则/主题/权力/历史/美学），据此派生**新世界**，
不动来源文件。`seed` 是"新世界的新变量"，`source` 是"保留的骨架"。

| 你的目标 | 选的操作 |
| --- | --- |
| 留住来源的核心规则，换一套社会/历史 | `深度变形`（seed 作为新条件） |
| 保住主题矛盾，换时代/制度/技术 | `主题移植` |
| 留住底层逻辑，写它没重点写的区域/时代 | `边缘扩展` |
| 反转一条关键假设，看连锁变化 | `反转前提`（会给多个具体反命题候选，你挑一个） |
| 让两套设定并存并处理冲突 | `世界交叉`（必须再加第二份材料 `--second`） |

```powershell
python world_studio.py graft "worlds/界河/world.md" --op 深度变形 --seed "一个新变量"
# 来源标注会带上项目目录：来源：界河/world.md（也可 --name 自定义）
```
导入后先看「嫁接变形记录」与「生成提示」（如有差异提示），再对自己认可的新增规则切状态 / 锁定，
必要时用 `edit` 改写条目。

## 五、设定状态、依赖与一致性

**四种状态**：`已确认 confirmed` / `候选 candidate` / `未决 open` / `有意保留的矛盾 contradiction`。

**结构化编辑**：可编辑任意条目的**名称 / 内容 / 依据 / 状态**——修改时**保留 id、来源与依赖关系**。
编辑**已锁定或已确认**的条目需要**确认**；**修改核心规则后，系统会列出需要复核的下游候选**（不静默覆盖）。
GUI 在左下“编辑选中条目”里改；命令行用 `edit`。

**依赖溯源**：条目依赖是 规则 → 后果 → 制度/历史 → 地理/冲突 的链，
可反查"改某条规则会牵连谁"：`python world_studio.py impact <目录名> rule-1`。

**一致性提示（只提示，不自动修正）**：合并同类重复、跨类别疑似冲突、规则 ↔ 下游专项检查；
每条带**依据**与**把握度**；接入真实模型可加做语义审阅（标注"需人工确认"）。
离线模式声明"不做语义判断"。

## 六、目录与文件

每个世界独立存放于 `worlds/<名称>/`：

- `world.md` — 面向阅读与分享的结构化世界观文档（最终产物）。
- `world.json` — 机器可读，用于下次打开继续编辑。
- `worlds/` 只保存在本地，不会提交到代码仓库。

## 七、命令行速查

| 命令 | 作用 |
| --- | --- |
| `spark "一句话"` | 发散出多个世界原型 |
| `spark "一句话" --pick 名称` | 发散→选择→生长→导出，一步完成 |
| `pick <目录名> idea-2` | 稍后回到该项目，选第二个原型 |
| `grow <目录名> [--pick 名称]` | 生长并导出（未选原型会报错，不静默选第一条） |
| `graft <文件> --op 反转前提` | 导入设定并变形（派生新世界） |
| `graft a.txt --op 世界交叉 --second b.txt` | 世界交叉（必须有第二份材料） |
| `check <目录名>` | 一致性提示（含依据/把握度/离线声明） |
| `show <目录名> --entries` | 列出全部条目（[状态] id｜类别｜名称＋锁定） |
| `state <目录名> consequence-1 confirmed` | 设置条目状态 |
| `lock <目录名> rule-1 [--off]` | 锁定 / 解锁条目 |
| `edit <目录名> rule-1 --statement "…" [--yes]` | 编辑条目（保留 id/来源/依赖；锁定或已确认需 --yes） |
| `impact <目录名> rule-1` | 修改该条目会牵连哪些设定 |
| `state <目录名> consequence-1 confirmed` | 设置条目状态 |
| `show <目录名>` / `list` | 查看状态 / 列出本地世界观 |

所有命令前可加 `--out <目录>` 指定数据根目录（默认 `worlds/`）。

## 八、接入真实模型

默认就走真实模型 opencode（复用你已登录的模型，含 OpenCode Go 订阅）；mock 是离线备选。

**opencode（默认，推荐）**

```powershell
opencode auth login opencode       # 一次性：用订阅登录（更新过 API key 后重做这一步）
opencode serve --port 4096         # 另开终端，保持运行
python world_studio_gui.py         # 顶部「模型」默认已选 opencode
```

默认模型为 `opencode-go/deepseek-v4.1-flash`；可用 `$env:NJE_OPENCODE_MODEL = "opencode-go/<模型>"` 覆盖。

**OpenAI 兼容端点（OpenAI / DeepSeek / Qwen …）**

```powershell
$env:OPENAI_API_KEY = "你的key"
$env:NJE_BASE_URL   = "https://api.deepseek.com/v1"
$env:NJE_MODEL      = "deepseek-chat"
# 顶部「模型」选 openai
```

离线备选：把「模型」切到 `mock`（或 `--provider mock`）。

模型返回的 JSON 会被严格校验（`kind` 白名单、最低类别覆盖、id 唯一、依赖引用有效、无环）；
不合格时忽略并**记录原因**、必要时**回退到离线推导**，且文档中会有提示。保存采用**原子写入并保留 `.bak` 备份**。

## 九、常见问题（FAQ）

| 问题 | 说明 |
| --- | --- |
| 导出到哪里？ | `worlds/<名称>/world.md`；也可在界面里「另存副本」。 |
| 能否只发散、不生长？ | 可以。点「发散」即已保存，之后可随时「打开」继续选原型。 |
| 生长会覆盖我确认的内容吗？ | 不会。已锁定 / 已确认的条目在再次生长时不会被改写。 |
| 嫁接会覆盖原世界吗？ | 不会。默认派生新世界，源世界保持原样。 |
| 为什么很多条目标"候选"？ | 这是刻意的：只有你确认后才成为事实。 |
| "未发现冲突"可以放心吗？ | 离线检查是启发式的，不看语义；接入真实模型可加做语义审阅。 |
| 能直接变成小说项目吗？ | 当前以"输出一份 world.md"为目标，作为写作参考使用。 |
